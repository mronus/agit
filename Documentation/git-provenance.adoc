git-provenance(1)
=================

NAME
----
git-provenance - Show, verify, adopt, purge and sum AI provenance of commits


SYNOPSIS
--------
[synopsis]
git provenance show [--reasoning] <commit>
git provenance verify [<commit>...]
git provenance adopt [--from <rev>]... [-f | --force] <revision-range>...
git provenance purge [--dry-run] <revision-range>...
git provenance purge [--dry-run] --session <id>... [<revision-range>...]
git provenance purge [--dry-run] [-E | -F] [-i] --redact <pattern>
		     [<revision-range>...]
git provenance stat [--porcelain] [<revision-range>...]

DESCRIPTION
-----------

Provenance records describe how the changes of a commit were made: a
line record says which added and removed lines were written by an AI
agent, by a human, or by both, and a reasoning record says why the
commit was made.  Records are stored as notes under
`refs/provenance/lines` and `refs/provenance/reasoning`, keyed by the
commit they describe, so a commit can carry provenance without its
object id changing.  See
`Documentation/technical/git-provenance-format.adoc` for the record
formats.  linkgit:git-commit[1] writes the records of each commit it
makes, and `git commit --amend`, linkgit:git-cherry-pick[1],
linkgit:git-revert[1] and linkgit:git-rebase[1] carry the records of
the commits they rewrite over to the commits they make (see their
PROVENANCE sections).

This command reads and checks records, gives records to commits made
without them from the records of the commits they were made from
(`adopt`), removes what reasoning records must not hold (`purge`),
and sums the line records of a range of history (`stat`).  See
linkgit:git-notes[1] for a way to attach a record by hand.

COMMANDS
--------

`show [--reasoning] <commit>`::
	Print the line record attached to _<commit>_ as it is stored.
	With `--reasoning`, print the reasoning record instead.

`verify [<commit>...]`::
	Check the line record attached to each _<commit>_ (`HEAD` if
	none is given) against the commit, and print one line per
	commit: `<object-id> ok` if the record verifies, or
	`<object-id> no record` if the commit has no line record.  If the
	record does not verify, describe the first problem found on
	standard error.
+
A record verifies if it is well formed, names the commit it is
attached to, uses only declared actors, lists no actors for the
ranges it marks `UNKNOWN`, and each of its ranges lies within
the file it names (in the commit for `+` ranges, in its first parent
for `-` ranges) and matches its anchor.

`adopt [--from <rev>]... [-f | --force] <revision-range>...`::
	Give records to commits that were made without the extension
	from commits that have records, such as the commit of a hosting
	service's "squash and merge", or one made by `rebase` or
	`cherry-pick` of a Git without the extension.  A single commit
	names that commit; a range such as `main@{1}..main` names the
	commits in it (see linkgit:gitrevisions[7]).  The commits are
	processed oldest first, and one line is printed per commit:
	`<object-id> adopted` if it was given records,
	`<object-id> no source` if no commit with a record accounts for
	any of its lines, `<object-id> has record` if it has a line
	record already, or `<object-id> merge` if it is a merge commit,
	which is not adopted.
+
The sources of a commit are the commits that have a line record, are
not in its history, and change a path that it changes.  Each line that
the commit changes takes its marks from the first source, oldest
first, that has the same line among the changes its record covers; a
line that rewrites such a line, or that no source accounts for, is
`UNKNOWN`.  A line is never guessed to be `HUMAN`: it is `HUMAN` only
if a source record marks it so, and its human is then the author of
the commit.  The reasoning record collects the sessions and summaries
of the sources that some line was taken from, and the line record is
marked `capture adopted`.  Nothing is written for a commit that no
source accounts for, so that it can be adopted once its sources have
been fetched.

`purge [--dry-run] <revision-range>...`::
`purge [--dry-run] --session <id>... [<revision-range>...]`::
`purge [--dry-run] [-E | -F] [-i] --redact <pattern> [<revision-range>...]`::
	Remove from the reasoning records what they must not hold, such
	as a secret that an AI session wrote into a summary.  Only
	`refs/provenance/reasoning` is rewritten.  Line records are left
	alone: they hold marks, session ids, and model and tool names,
	but no free text.  Commits are named as for `adopt`.
+
--
_<revision-range>_ alone;;
	Remove the reasoning records of the commits.
`--session <id>`;;
	Drop the `session` line of _<id>_ from each reasoning record that
	has one, or from those of the given commits.  The summary of such
	a record is dropped as well, as it cannot be told which session
	wrote what, and a record left without a `session` line is removed,
	as it would state that no AI was involved.  Can be given more
	than once.
`--redact <pattern>`;;
	Replace each match of _<pattern>_ in the summary of each
	reasoning record, or of those of the given commits, with
	`***REMOVED***`.  The `version`, `commit` and `session` lines are
	never changed.
--
+
A record that none of these changes is kept as it is, as is a record
that cannot be parsed, with a warning.  One line is printed per record
that is changed: `<object-id> removed`, `<object-id> redacted <n>`
with the number of matches replaced, or `<object-id> session
dropped`, where _<object-id>_ names the commit of the record.
+
The records that are left are written as one new commit of
`refs/provenance/reasoning` without a parent, so that neither the
purged records nor the history of the ref that held them can be
reached from it any more; nothing is written if no record is changed.
The old records still exist until they are dropped: replace the ref
of the remote with `git push --force <remote>
refs/provenance/reasoning`, which also updates its tracking ref (see
linkgit:git-push[1]), and then run `git reflog expire --expire=now
refs/provenance/reasoning` and `git gc --prune=now` in this
repository.  Other clones take the rewrite with their next fetch,
which keeps the records they added since (see linkgit:git-fetch[1]).
A clone that pushes its own `refs/provenance/reasoning` with `--force`
without fetching first brings the purged records back, as it would
for any rewritten history; so does a copy made by other means, such
as a mail or a backup.

`stat [--porcelain] [<revision-range>...]`::
	Sum the line records of the commits in _<revision-range>_ and
	print how many lines they add and remove, by mark, and the share
	of the added lines that are `AI` or `MIXED`.  The commits are
	walked as linkgit:git-log[1] walks them: without a range, the
	history of `HEAD`; a single commit names its history, not that
	commit alone as for `adopt` and `purge` (`<commit>^!` names one
	commit).  Options that limit the walk, such as `--since` or
	`--author`, are taken as `git log` takes them; paths are not.
+
A commit without a line record is counted, but adds no lines; a
record that cannot be read or parsed is skipped with a warning, and
its commit counts as one without a record.  The share is computed as
`%(provenance:share)` computes it for one commit (see
linkgit:git-log[1]): the `AI` and `MIXED` lines among the added lines,
rounded to the nearest percent.  Each count of a mark is followed by
its part of the lines added or removed:
+
------------
commits    4  (3 recorded)
added     15  AI 3 (20%)  MIXED 1 (7%)   HUMAN 8 (53%)  UNKNOWN 3 (20%)
removed    6  AI 1 (17%)  MIXED 1 (17%)  HUMAN 2 (33%)  UNKNOWN 2 (33%)
share    27%
------------

OPTIONS
-------

`--reasoning`::
	Show the reasoning record instead of the line record.

`--from <rev>`::
	With `adopt`, only take records from commits that _<rev>_ can
	reach, such as the branch that was squashed.  Can be given more
	than once.

`-f`::
`--force`::
	With `adopt`, replace the records of commits whose line record
	was adopted.  Both records are replaced: a commit adopted again
	from sources that name no session keeps no reasoning record.
	Records that were observed or declared are never replaced.

`--porcelain`::
	With `stat`, print one `<key> <value>` line per count, in a form
	meant for scripts: the keys are `commits`, `recorded` (the
	commits with a line record), `added`, `added.ai`, `added.mixed`,
	`added.human`, `added.unknown`, `removed`, `removed.ai`,
	`removed.mixed`, `removed.human`, `removed.unknown` and `share`,
	in this order, and the share is a number without a `%` sign.

`-n`::
`--dry-run`::
	With `purge`, print what would be purged, without writing
	anything.

`--session <id>`::
	With `purge`, drop the session _<id>_ from the reasoning
	records.

`--redact <pattern>`::
	With `purge`, replace the matches of _<pattern>_ in the summaries
	of the reasoning records.  _<pattern>_ is a basic regular
	expression, as `git log --grep` takes it, and matches within a
	line.

`-E`::
`--extended-regexp`::
	With `--redact`, _<pattern>_ is an extended regular expression.

`-F`::
`--fixed-strings`::
	With `--redact`, _<pattern>_ is a fixed string, such as a leaked
	key, whose characters have no special meaning.

`-i`::
`--regexp-ignore-case`::
	With `--redact`, match _<pattern>_ ignoring case.

EXIT STATUS
-----------

`show` exits with status 0 if the record exists, and 1 if it does
not.  `verify` exits with status 0 if every record that exists
verifies, and 1 otherwise; a commit without a record is not a
failure.  `adopt` exits with status 0 unless an error occurred, such
as a record that could not be written; a commit for which no source
is found is not a failure.  `purge` exits with status 0 unless an
error occurred, also when there is nothing to purge.  `stat` exits
with status 0 unless the line records cannot be read; a commit without
a record, or with one that does not parse, is not a failure.  All of
them exit with status 128 if an argument is not a commit.

SEE ALSO
--------
Other commands show provenance records as well: `git diff`, `git show`
and `git log -p` mark each line of a patch with `--provenance` (see
linkgit:git-diff[1]), `git blame --provenance` marks each line of a
file (see linkgit:git-blame[1]), and the `%(provenance:<field>)`
placeholders of the pretty formats show the summary, the AI share,
the models and the sessions of a commit (see linkgit:git-log[1]).

`git fetch`, `git pull`, `git clone` and `git push` transfer the
records along with the branches and merge the records of a remote
into the local ones (see the PROVENANCE sections of
linkgit:git-fetch[1] and linkgit:git-push[1]).  `git format-patch`
carries the line records in patch mails and `git am` records them for
the commits it makes, and `git fast-export` and `git fast-import`
carry the provenance refs when they are named or with `--all` (see
the PROVENANCE sections of linkgit:git-format-patch[1],
linkgit:git-am[1], linkgit:git-fast-export[1] and
linkgit:git-fast-import[1]).
